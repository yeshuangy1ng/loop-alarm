# 循环闹钟 · Loop Alarm

按时间间隔循环提醒的 Chrome 浏览器插件（Manifest V3）：以**分组**管理闹钟，分组可设置**生效时间段**和**启用开关**、可**改名**；到点时在**当前页面右上角弹出提醒卡片**，支持**点击关闭**和**稍后提醒（5/10/30 分钟）**。

## 功能

- **循环闹钟**：每条闹钟按固定间隔（小时 + 分钟）循环提醒
- **分组管理**：
  - 分组名称（可改名）、启用/停用开关
  - 生效时间段（每日，如 09:00–17:00）
    - 开始 > 结束 视为跨午夜（如 22:00–06:00）
    - 开始 = 结束 视为全天
  - 分组下的闹钟可单独启用/停用
- **闹钟字段**：名称、提醒文案、间隔（小时/分钟）、可选开始时间（首次提醒时刻，留空 = 从当前时刻起按间隔循环）
- **段外跳过**：提醒时刻落在分组生效时间之外时跳过该轮，按间隔继续；
  选项页「下次提醒」会标注「时刻在生效时间段外，将按间隔步进到段内再提醒」
- **配置变更立即生效**：
  - 改间隔 → 立即重新锚定：开始时间在未来时首次提醒仍是开始时间；
    未设开始时间或开始时间已过（循环进行中）→ 从当前时刻按新间隔重新起算
  - 设置/清空开始时间 → 取消挂起的「稍后提醒」（否则稍后时刻优先，新开始时间会被遮蔽）
  - 保存即触发后台重新排程（串行化，避免并发排程竞态）
- **提醒卡片**：到点在当前页面右上角弹出卡片（内容脚本注入），可逐条「稍后提醒」或「关闭」；
  点击「稍后提醒」后条目收起，全部处理完自动关闭；当前页无法显示时（chrome 内部页等）回退为打开新标签页提醒卡
- **角标倒计时**：工具栏图标显示距下一次提醒的时间（每分钟刷新，统一分钟级精度，如 `30m` / `1h` / `<1m`）
- **毫秒级准点触发**：先「提前唤醒」再「精确等待」，把平台闹钟的唤醒抖动与弹窗时刻解耦
  （平台闹钟只负责把 Service Worker 提前约 20 秒叫醒，到点触发由精确计时器完成，误差毫秒级），
  并额外排一个兜底闹钟，确保极端情况下也不漏提醒
- **按计划网格锚定**：触发时刻晚几十秒也不会被写进后续轮次——「每 30 分钟」始终落在整点/半点，
  不会因为第一次晚了 37 秒就变成之后每轮都晚 37 秒
- **运行诊断**：选项页左下角显示实际排程方式（一次性闹钟 / 降级轮询）与最近触发偏差统计
- **补提醒**：浏览器重启后，错过的提醒补提醒一次并重新锚定循环
- **导入 / 导出**：选项页一键导出全部配置为 JSON 文件，或从 JSON 文件导入（覆盖现有分组，字段自动清洗）
- 数据保存在 `chrome.storage.local`，浏览器重启不丢失

## 安装

1. 打开 Chrome，进入 `chrome://extensions/`
2. 右上角开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本目录（包含 `manifest.json` 的目录）
4. 安装完成会自动打开选项页；点击工具栏图标可打开弹窗

> 提醒依赖浏览器运行：浏览器完全关闭时无法提醒；浏览器打开期间（含标签页最小化）由 `chrome.alarms` 精确唤醒。
>
> 扩展需要 `scripting` 权限：用于把提醒卡片注入到扩展加载后才打开的页面（常规页面由静态内容脚本覆盖，无需动态注入）。

## 使用

- **工具栏弹窗**：快速查看各分组状态、启用/停用、删除分组；点击分组名进入选项页编辑
- **选项页**（「完整管理」按钮或 `chrome://extensions` 中打开）：
  - 左侧分组列表 + 新建/删除分组
  - 「导出配置」：下载全部配置为 JSON 文件（文件名含时间戳）
  - 「导入配置」：选择 JSON 文件覆盖现有分组（导入前确认；缺失字段自动补默认值，非法字段自动纠正）
  - 右侧分组设置（名称 / 生效时间段 / 启用）+ 闹钟列表（名称 / 文案 / 间隔 / 开始时间 / 启用 / 删除 / 添加）
  - 修改即自动保存，并实时显示「下次提醒」时间
  - 左下角「运行诊断」：显示实际生效的排程方式与最近触发偏差（毫秒级可验证）
- **提醒卡片**：到点自动出现在你当前浏览的页面右上角
  - 每条提醒可点「5 / 10 / 30 分钟后提醒」（稍后提醒优先于原循环，触发后循环从稍后时刻重新起算）
  - 点击「稍后提醒」后该条目立即收起，所有条目都处理后卡片自动关闭；新标签页提醒卡在全部处理后自动关闭标签页
  - 点「✕ 关闭」收起卡片（刷新页面也会消失）
  - 当前页无法注入时（如 chrome:// 内部页），回退为打开新标签页提醒卡

## 调度语义说明

- 到期时间 = 稍后提醒时刻（若设置了）或循环锚点 `nextFire`
- 已到期且当前在生效时间段内 → 触发提醒，`nextFire = 计划时刻 + k×间隔`
  （k 取最小使结果 > 实际触发时刻；用计划时刻而非实际触发时刻锚定，唤醒抖动不会被固化进后续轮次）
- 已到期但当前在段外 → 不触发，按间隔步进到下一个段内时刻（跳过该轮）
- 浏览器重启后错过的提醒 → 补提醒一次，`nextFire` 落到下一个网格点
- 精度实现（两级）：
  1. **提前唤醒**：排程在「目标时刻 − 20 秒」叫醒 Service Worker。
     依次探测 `when` → `delayInMinutes` → `periodInMinutes`，取浏览器支持的第一种；
     都不支持时降级为 30 秒周期轮询（Chrome 允许的最小周期，更小会被钳制）。
  2. **精确等待**：SW 唤醒后若距目标已进入 27 秒窗口，用精确计时器等到点再触发；
     等待期间每 10 秒调一次扩展 API 心跳，避免 SW 被 30 秒空闲回收。
  于是 `chrome.alarms` 只负责"粗唤醒"，到点触发由精确计时器完成 → 弹窗误差毫秒级。
  （背景：`chrome.alarms` 官方精度为 30 秒粒度且可能被任意延后，直接用它决定弹窗时刻必然错位几十秒）
  3. **兜底闹钟**：一次性模式下额外排一个「目标时刻之后一点点」的闹钟。
     即使 SW 在精确等待期间被回收、或提前唤醒闹钟丢失，也会被叫醒并补提醒（最坏等于退回旧精度，不漏提醒）。
- 闹钟由浏览器持久化，Service Worker 被杀也能唤醒；唤醒点封顶 59.5 分钟（防极端远未来值），到期后链式重排
- 配置变更重新排程：任意保存（选项页 / 弹窗）立即触发后台重新排程；
  排程与触发都串行化执行，避免并发排程竞态残留过期的一次性闹钟、并发触发重复提醒
- 配置变更生效语义：
  - 改间隔 → 立即重新锚定（开始时间在未来：首次提醒仍是开始时间；否则从当前时刻按新间隔起算）
  - 设置 / 清空开始时间 → 取消挂起的「稍后提醒」（稍后提醒优先，不清除会遮蔽新开始时间）
  - 选项页对后台变更（触发后推进、稍后提醒等）按内容比对同步，
    避免旧版 800ms 时间窗误判把真实外部变更当自写丢弃、进而被过期状态覆盖
- 角标由独立的 1 分钟周期闹钟（`badge-tick`）每分钟刷新（分钟级精度），
  一次性排程模式下（两次触发之间无 tick）角标也不会停更。
- 已知边界：浏览器完全关闭时不唤醒；浏览器整体休眠/挂起后由系统恢复时，
  第一次触发可能补提醒（语义同"错过的提醒补一次"），之后回到准点网格。

## 目录结构

```
manifest.json        MV3 清单（权限：storage / alarms / scripting）
background.js        Service Worker：排程 / 触发 / 角标 / 提醒投递（前台页卡片 → 新标签页回退）
content.js           内容脚本：当前页面右上角提醒卡片（稍后提醒 / 关闭）
shared/logic.js      核心调度纯逻辑（浏览器 + Node 通用）
popup.html/.js       工具栏弹窗：快速查看与开关
options.html/.js     选项页：分组 / 闹钟完整管理
reminder.html/.js    提醒卡片页
icons/               图标（16/32/48/128）
tools/gen-icons.js   图标生成脚本（纯 Node，无依赖）
test/test-logic.js   核心逻辑单测
test/test-simulate.js 端到端循环模拟测试
test/test-pages.js   页面 / Service Worker 冒烟测试（DOM + chrome API 桩）
```

## 测试

```bash
node test/test-logic.js     # 核心调度逻辑（52 项断言）
node test/test-simulate.js  # 模拟后台 tick 的完整循环语义
node test/test-pages.js     # 页面 / Service Worker 冒烟测试（含配置变更重新锚定回归）
node tools/gen-icons.js     # 重新生成图标
```

## 数据格式（chrome.storage.local）

```jsonc
// key: "state"
{
  "version": 1,
  "groups": [{
    "id": "g_xxx",
    "name": "工作时段",
    "enabled": true,
    "start": "09:00",
    "end": "17:00",
    "alarms": [{
      "id": "a_xxx",
      "name": "站立活动",
      "text": "起来活动 5 分钟",
      "intervalMinutes": 90,
      "startTime": 1700000000000,   // 可空；null = 立即按间隔起算
      "enabled": true,
      "nextFire": 1700000900000,    // 循环锚点（epoch ms）
      "snoozedUntil": null          // 稍后提醒时刻（epoch ms），优先于 nextFire
    }]
  }]
}
// key: "pendingReminders"：{ "batches": { "<batchId>": { batchId, firedAt, items: [...] } } }
// key: "scheduleInfo"：{ mode: "when"|"delay"|"poll"|"idle", target, at }   // 运行诊断
// key: "fireStats"  ：{ n, sum, last, max }                                // 触发偏差统计（ms）
```

导出文件格式（「导出配置」下载的文件）：

```jsonc
{
  "app": "alarmclock",
  "version": 1,
  "exportedAt": "2025-01-01T09:00:00.000Z",
  "state": { /* 完整 state 结构，如上 */ }
}
```

导入兼容三种结构：上述包裹格式 / 裸 `state` 对象（含 `groups`）/ 裸 `groups` 数组。
